# 几步走计划（2026-11-06，用户拍板开工）

目标：做一个能给别人用的系统。别人的 agent 挂上我们的 MCP/skill，就能查设计规范和业务知识库、生成 demo；每轮的产物、用户原话、自评好坏自动记下来传回云端；云端再把这些反哺回知识库。

## 第一步：做一个 skill 文件夹（先本地跑通，不做插件、不搭 MCP）
- 用户侧只做一次操作：复制一个文件夹到 ~/.qoder/skills/（或一条 npx 命令安装）。不用分清 MCP 还是 skill，里面是什么用户不用管。
- 文件夹里有什么：SKILL.md（先查规范再生成、每轮结束调记录脚本、自评）+ scripts/（复用原型 recorder/uploader/sanitizer）+ knowledge/（设计规范 YAML 示例 + 业务知识库示例）。
- 为什么不用插件：开发成本高、上平台要审核；Qoder 官方文档确认 skill 不用插件也能装（用户级 ~/.qoder/skills/、项目级 .qoder/skills/）。
- 为什么不用 MCP：本地这一步脚本就能做完读规范、记一轮、上传，不用多跑一个服务；以后要给程序调用再加 MCP。
- 代价：每轮记不记靠 agent 按 skill 做，没有钩子兜底；跑一阵看效果，不行再加插件/钩子那层。
- 顺序：先本地跑通（装上→查知识→生成→记一轮→传到本地接收端），再上云。云端先复用 judgment-pipeline-proto 原型。

## 第二步：记录与上传自动跑起来
- 每轮结束自动记一条，本地先存，攒够或会话结束自动传；断网排队、失败重试。
- 传之前本地脱敏，同意开关默认关。

## 第三步：云端用 kbase MCP + 云端 agent 整理（不自己搭后台数据库）
- 回传：本地上传脚本直接调 kbase MCP 服务写进去（脚本当客户端调），不用靠 agent 记性。
- 存两层：原始区每轮原样存（查账用）；知识区只存提炼后的规则（带支持次数、接受率、来源）。
- 质量：云端 agent 定期整理——去重、合并、过滤一次性意见、算接受率，够格才进知识区；冲突的标给管理员看。
- skill 改读 kbase：知识以后从 kbase 现读，不放 skill 文件夹里；云端一改，所有人下次挂上就拿到新的。
- 待确认（2026-11-06）：kbase MCP 有没有写工具、认证怎么拿、单条能写多大、云端 agent 跑在哪。

## 第四步：云端反哺知识库
- 意见攒够了提炼成规则（Agentic Cortex 三件套 + ClawHub 晋升线），更新知识库；下次别人挂载就拿到新版。

## 第五步：给别人用
- 打包、分发、权限、同意开关；量够了再谈模型微调。

## 约束（用户原话）
- 规划简明易懂，先讲怎么做、再讲做什么，少用技术词。
- 本地 agent 用 Qoder，不用 Claude Code。
