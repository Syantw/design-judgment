# 设计判断（design-judgment）

这个 skill 帮你按品牌的设计规范和业务知识库生成界面 demo，并且把你和用户在每轮对话里的设计判断记下来，传回云端。

## 先读什么

动手画 demo 之前，先读这两个文件（都在 skill 文件夹的 knowledge/ 里）：

- `knowledge/spec.yaml`：设计规范，品牌色、字号、间距、组件长什么样都在里面。
- `knowledge/knowledge.md`：业务规则，哪些东西页面上必须有、哪些不能错。

生成时只用规范里有的颜色、字号和组件。规范里没有的，不要自己发明。

## 工作流

1. **读规范和知识库**：先读上面两个文件，再动手。
2. **生成 demo**：按用户说的画一版完整、可点的界面 demo。
3. **自己先审一遍**：对照下面的检查表看一遍，不合规范的改完再给用户。
   - 颜色、字号、间距是不是规范里的
   - 用的组件对不对，主按钮是不是每屏只有一个
   - 业务知识库里的必备内容有没有少
4. **每轮结束记一条**：用户每回一句话（改哪里、接受还是打回），就运行一次记录脚本，把四样东西绑在一起记下来：用户原话、这一轮的 demo、改了什么、接受还是打回。命令：
   ```
   python3 <skill目录>/scripts/record.py --session-id <会话编号> --round <第几轮> --user-text "<用户原话>" --demo-snapshot <demo 文件路径或 HTML> --diff "<改了什么>" --result accepted|rejected
   ```
   round 从 1 开始，每轮加 1；同一个会话里 session-id 不要变。`<skill目录>` 换成这个 skill 文件夹的实际路径。
5. **会话结束传一次**：用户说做完了，或者会话要结束时，运行上传脚本：
   ```
   python3 <skill目录>/scripts/upload.py
   ```
   上传之前要先拿到用户同意（见下面）。

## 记录之前先脱敏

记录脚本会自动把敏感内容换成 *** 再存（比如人名、公司名、手机号、邮箱）。不用你手动处理，但也不要把敏感内容写进 --diff 里。

## 上传要先同意

上传默认是关的。用户同意之后才能传，同意的办法：

- 让用户把环境变量 JUDGMENT_UPLOAD 设成 1，或者
- 在 skill 文件夹的 data/consent.json 里写 `{"upload_enabled": true}`。

没同意就只记在本地，不往外传。

## 没联网也能记

记录只写本地，不用联网。上传时没网也没关系，记录会排队等着，下次上传时自动补上。

## 记录存在哪

记录存在 skill 文件夹的 data/ 里（client.db 是账本，snapshots/ 是每轮 demo 快照），不会写到别处。
